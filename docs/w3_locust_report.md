# 加速W3: Locust 压测报告（2026.11.19）

## 压测环境
- 环境：Docker 容器（CPU 限制）
- 接口：`/retrieve`（C++ 分词 -> Chroma 检索 -> BGE-reranker 重排）
- 压测工具：Locust 2.47.0

## 测试结果对比
| 并发数 | 失败率 | QPS | P50 延迟 | P99 延迟 | 瓶颈分析 |
|--------|--------|-----|----------|----------|----------|
| 20并发 | 0% | ~1.4 | 5.0s | 52s | CPU 饱和，严重排队 |
| 5并发 | 0% | ~1.5 | 2.5s | 7.3s | BGE-reranker 计算密集，阻塞主线程 |

## 瓶颈分析
通过压测发现，即使降低并发到 5，P99 延迟依然在 7 秒以上。定位瓶颈在于 **BGE-reranker-base 模型的 CrossEncoder 推理**。由于目前运行在无 GPU 的 Docker 容器中，CPU 算力不足以支撑高并发下的 Transformer 推理。

## 优化方案
1. **引入批处理**：将单条重排改为批次重排，减少模型调用次数。
2. **降级策略**：在并发极高时，跳过 BGE-reranker，直接使用 Chroma 的向量相似度结果。
3. **改用 API 或 GPU**：使用外部重排 API，或将模型部署在支持 GPU 的环境中。
